**这份文档是产品架构的锚点 —— 设计模式的唯一家。**

它只回答一个问题:**这台机器是什么、概念怎么组织、层次怎么分**。它不回答:

**设计模式的先后:先立骨架(本文件),插件(具体动作实现)后做。** 骨架没立住就谈插件是本末倒置。

骨架正向**时间轴编辑器**演进(设计定稿见 [`TIMELINE.md`](./TIMELINE.md)),插件层已落地 —— 扩展点怎么用看 [`PLUGINS.md`](./PLUGINS.md)。本文件仍只讲概念,不讲接口。

## 一句话定位

**通用可编程空间定位平台。**

卖的不是"摄影臂",是**"把任意空间位置+姿态变成可一键到达、稳定保持、可编程触发的资源"**。摄影是这个资源的第一个实例,不是产品的全部 —— 产品摄影、3D 扫描、质检巡检、布光、示教回放、可编程工装,都是同一套内核上的不同组装。

空间定位能力早已立住;新一版交互骨架补上的是它在**时间维度的呈现** —— 空间编排以时间轴的形式被看见、被修剪、被播放。

## 三个不变量(骨架,永不动)

```
① 内核 Kernel        空间定位能力:move_to / hold / settle / 急停 / 安全闸门
                      —— 场景无关,是物理地基,永不动

② 交互骨架 Skeleton   素材库 / 编排轨道(站位 ⇄ 时间轴双密度,单一编辑器) / 监视器 / 预演与执行
                      —— 场景无关,一份界面,所有用户共用

③ 插件 Plugins        动作的具体实现:快门 / 夹爪 / 传感器 …
                      —— 场景相关,可插拔,后做
```

**模式的先后就是这三层的先后**:内核是地基(已有),交互骨架是承重结构,插件是装修。插件随时换,骨架不能塌。

## 概念模型:无领域积木

| 积木 | 定义 | 性质 |
|---|---|---|
| **位姿 Pose** | 一个命名的"位置+姿态"(含夹爪),拖臂录制,住素材库 | 最小单元,链接式复用 |
| **序列 Sequence** | 保持块与过渡块交替排成的一整条时间轴,事件标记钉在块内 | 编排的唯一形态 |
| **动作 Action** | 末端负载的可触发操作(抽象接口),钉在序列的块内标记上 | 插件的挂载点 |
| **模板 Template** | 序列的结构配方(不含关节角),复印+向导实例化后脱钩 | 起步包 |

**场景 = 用户用积木组装出来的结果,不是产品预设的模式。**

像 Notion:底层是无领域含义的积木,普通人当笔记本、仓库管理员搭成设备库,产品里**没有"模式切换"**。这里的"模式切换"指**领域场景模式**(摄影/质检那种封闭盒子);编排轨道的「站位 ⇄ 时间轴」是同一编辑器、同一模型的两个渲染密度,不是场景模式。同理,产品**不知道、也不关心**一个位姿叫"机位"还是"工位" —— 那是用户起的名字。每个部署实例被一个用户组装成固定形态,之后就固定在那个形态里用,永不切场景。

「集合」不再是独立积木:素材库与序列列表就是容器,分组等真有人需要再长。

## 配置与使用分层

```
配置层(偶尔,像 Notion 搭页面)      使用层(天天,像 Notion 用页面)
  拖臂 → 录位姿                      点位姿卡「去这里」→ 臂到位 → 触发
  编时间轴 / 存模板 / 起名            或:点「执行」跑整条序列
```

摄影师搭好"四方位"后很少回配置层;日常就在使用层。**原子操作不变:到位 → 稳定 → 触发 → 停住**,变的只是它住进了素材库;编排好的序列则经时间轴一键执行。

## 模板机制(解决低门槛)

模板 = **预组装好的结构配方**(如"产品拍摄"模板 = 四站位 + 每站停 3 秒 + 每站一张快门 + 过渡 2 秒缓入缓出),**不含关节角** —— 别台机器、别的棚里示教的角度在你的棚里是错的,模板的价值是结构。

实例化 = 复印 + 向导:逐站位引导示教位姿并绑定,生成普通序列,**复印即脱钩、两不相干**。模板进了用户手里就溶解成通用积木 —— 可改、可删、可从空白重搭。这区分于"场景切换":场景是个封闭盒子,用户只能在盒子里操作;模板是别人搭好的积木,用户可以接着搭。

## 词汇基调

全界面**中性词**,不出现领域词:

| 用 | 不用 |
|---|---|
| 位姿 | 机位 / 方向 / 点位 / 锚点 |
| 站位 | 步骤 / 环节 / 工序 |
| 动作 | 特效 / 脚本步骤 / 标记 |
| 过渡 | 转场 |
| 预演 / 执行 | 播放(歧义动词) |
| 序列 | 播放列表 / 程序 |
| 模板 | 场景 / 模式 |

**站位 = 一个保持块 + 块内动作 + 出向过渡**,是用户面向的任务流词;「时间轴」是编排轨道精修密度的用户名。保持块 / 事件标记退为**工程词**,只出现在代码与文档里,界面不出现。

领域词由用户起名时自己用("这个位姿叫正面")。

**「锚点」一词退役。** 它曾是最小单元的名字,但那套房子同时指素材和序列里的引用 —— 两种东西共用一个词正是混淆的来源。现在素材叫位姿、序列里的块叫保持块,各回各家。

## 模式的先后边界

- **先定**:概念模型、分层、词汇(本文件)—— 骨架
- **后做**:插件(ESP32 快门是第一个动作插件)、场景模板 —— 骨架下的填充

插件层收敛成**三个扩展点而不是一个 hook 链**:动作插件(进程内,流程会等它)、触发源(进程外 HTTP 客户端)、事件订阅(进程外 WS 客户端)。为什么是三个、为什么触发源不能是进程内回调,见 [`PLUGINS.md`](./PLUGINS.md)。

摄影场景需要的"单次到位+拍"(点位姿 → 到位 → 稳定 → 触发 → 停住)是**使用层原子操作的最小闭环**,也是所有场景的公共操作,先于任何插件存在。

## 模式的对错,由摄影场景验证

这个模式是从摄影场景倒推收敛的,它的试金石是:**摄影场景能否用这套积木 100% 表达出来,且不为"通用"付任何专用税**。能,模式成立;不能,说明抽象漏了东西 —— 那就修抽象,不是给摄影开后门。
