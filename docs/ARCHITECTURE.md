## 一句话定位

**开源 AIoT 机械臂参考方案。核心能力是「时空编程序列」:手掰示教、时间轴编排、一键回放。**

卖的不是某一台专用机器,而是**把"任意空间位置 + 姿态 + 时间"变成可录制、可编排、可回放的资源**。摄影(商业广告、产品拍图)是第一个**参考场景**,不是产品身份;工业场景可以探索。下游厂商在自己的业务里组装它 —— **平台赋能,下游管场景**。

**名称是双语言:**

- 产品线名 **Teach & Repeat · 示教回放** 是行业词,给懂行的下游厂商;
- 白话故事叫 **动作录制与回放** ——「手掰一遍,它记住;按一下,它重复」,给 demo 前站着的所有人;
- 场景层可以用自己的术语(文案级替换,不做术语引擎)。

**演示载体是真臂。** 3D 数字孪生谁都能做,是标配不是卖点;「让他们看到」看的是真臂效果。

## 两层架构:平台层 + 参考场景层

单仓库、显式分层。**分层是认知,不是仪式** —— 架构真有问题就大改,不抠无谓细节;拆仓是分发策略,等有真实下游再考虑。

```
平台层(我们交付,下游继承)
  ① 内核 Kernel        空间定位能力:move_to / hold / settle / 急停 / 安全闸门
                        —— 场景无关,是物理地基,永不动
  ② 时空编排引擎        位姿 / 序列 / 模板 / 时间轴 + 执行器 —— 场景无关
     + 参考 UI          剪辑隐喻的时空编辑器,平台自带;下游可以不用它、直接打 API
  ③ 插件系统           动作 / 操作 ops / 触发源 / 事件订阅(见 PLUGINS.md)
  ④ API + 租约         下游开发者与外部智能的入口

参考场景层(我们示范,下游替换)
  · 摄影(旗舰场景)      快门插件、演示数据、场景文案
  · 未来               工业;VLM 语音(证明「我们能实现」—— 感知不进内核)
```

场景层的内容以**插件 + 数据 + 文案**的形态落在平台扩展点上,不为任何场景开平台后门。

## 出厂 vs 场景落地:什么现在做、什么以后做

分层的**时间维度**:出厂交付的是内核 + 空插座,场景内容一律在实地落地那天才拼。排序不是"先做摄影再扩展",而是**先把内核闭环跑通,场景一个都不提前做**。

| 层 | 出厂交付 | 实地落地才拼 |
|---|---|---|
| 内核 Kernel | `move_to` / `hold` / 急停保持 / 运动闸门 —— 已存在 | — |
| 时空编排引擎 + 参考 UI | 位姿 / 序列 / 模板 / 时间轴 / 执行器 —— 已存在 | — |
| 插件系统 | **四个空扩展点(插座)** —— 只交付接口,不交付实例 | payload / action / trigger / 事件订阅的**具体实例** |
| 场景内容 | 无 | 场景序列 + 演示数据 + 场景文案 |

**场景落地 = 往插座上插四样东西**:payload(挂什么质量)+ action(快门/相机/夹爪/转台)+ trigger(外触发)+ 场景序列。拼法固定、内容替换 —— 摄影是第一个照此拼出的示范,工业/语音是后面的考卷。**不为任何假设的场景预先开发插件**;出厂应用里的插件是空的,场景到位那天才写。

**逐关节重力修正不在这张表的任何一格** —— 它不是配件、不是场景功能,而是一次性标定(手段):它服务的是内核「示教」动词本身的物理前提(零力拖动)。标定完它就不作为功能存在;不标定,手掰示教只在肘未展开的姿态可靠。重力模型本身仍走 vendor(铁律 4,不重造),k/c 修正只是 tuning 层的一次性标定值。

## 概念模型:时空编排积木

| 积木 | 定义 | 性质 |
|---|---|---|
| **位姿 Pose** | 一个命名的"位置+姿态"(含夹爪),拖臂录制,住素材库 | 最小单元,链接式复用 |
| **序列 Sequence** | 保持块与过渡块交替排成的一整条时间轴,事件标记钉在块内 | 编排的唯一形态 |
| **动作 Action** | 末端负载的可触发操作(抽象接口),钉在序列的块内标记上 | 插件的挂载点 |
| **模板 Template** | 序列的结构配方(不含关节角),复印+向导实例化后脱钩 | 起步包 |

**场景 = 用户用积木组装出来的结果,不是产品预设的模式。** 像 Notion:底层是无领域含义的积木,普通人当笔记本、仓库管理员搭成设备库,产品里**没有"模式切换"**。这里的"模式切换"指**领域场景模式**(摄影/质检那种封闭盒子);编排轨道的「站位 ⇄ 时间轴」是同一编辑器、同一模型的两个渲染密度,不是场景模式。同理,产品**不知道、也不关心**一个位姿叫"机位"还是"工位" —— 那是用户起的名字。每个部署实例被一个用户组装成固定形态,之后就固定在那个形态里用,永不切场景。

**夹爪也是插件 —— 但它是中介能力。** 夹爪电机在臂的同一条 CAN 总线上(电机 id 0x07),由控制循环持有;所以夹爪动作拿到的是宿主给的中介句柄(开/合/位置),命令进控制循环自己的队列、过急停闩锁与限位。插件**永远够不到六个臂关节** —— 铁律的精神在这里完整成立。夹爪是可换装件:摄影场景卸下夹爪、连接器直插相机,负载三态(bare / camera / gripper)已表达这个物理事实。

「集合」不是独立积木:素材库与序列列表就是容器,分组等真有人需要再长。

## 配置与使用分层

```
配置层(偶尔,像 Notion 搭页面)      使用层(天天,像 Notion 用页面)
  拖臂 → 录位姿                      点位姿卡「去这里」→ 臂到位 → 触发
  编时间轴 / 存模板 / 起名            或:点「执行」跑整条序列
```

摄影师搭好"四方位"后很少回配置层;日常就在使用层。**原子操作不变:到位 → 稳定 → 触发 → 停住**,变的只是它住进了素材库;编排好的序列则经时间轴一键执行。

## 模板机制(解决低门槛)

模板 = **预组装好的结构配方**(如"产品拍摄"模板 = 四站位 + 每站停 3 秒 + 每站一张快门 + 过渡 2 秒缓入缓出),**不含关节角** —— 别台机器、别的棚里示教的角度在你的棚里是错的,模板的价值是结构。

实例化 = 复印 + 向导:逐站位引导示教位姿并绑定,生成普通序列,**复印即脱钩、两不相干**。模板进了用户手里就溶解成通用积木 —— 可改、可删、可从空白重搭。这区分于"场景切换":场景是个封闭盒子,用户只能在盒子里操作;模板是别人搭好的积木,用户可以接着搭。

## 词汇基调

全界面**中性词**,不出现领域词:

| 用 | 不用 |
|---|---|
| 位姿 | 机位 / 方向 / 点位 / 锚点 |
| 站位 | 步骤 / 环节 / 工序 |
| 动作 | 特效 / 脚本步骤 / 标记 |
| 过渡 | 转场 |
| 预演 / 执行 | 播放(歧义动词) |
| 序列 | 播放列表 / 程序 |
| 模板 | 场景 / 模式 |

**站位 = 一个保持块 + 块内动作 + 出向过渡**,是用户面向的任务流词;「时间轴」是编排轨道精修密度的用户名。保持块 / 事件标记退为**工程词**,只出现在代码与文档里,界面不出现。

领域词由用户起名时自己用("这个位姿叫正面")。

**产品身份词的分层**:「参考方案」是产品身份;「示教回放」是产品线名 / 行业词;「动作录制与回放」是白话故事主语。场景层(如摄影)可以用自己的术语,替换只发生在文案层,不做术语引擎。

**负载(payload)** 是调参面板面向操作者的词:末端挂的是什么。工程词是 **payload profile**,三态枚举 —— `bare`(裸臂,无夹爪无相机)/ `camera`(相机装在夹爪位,需称重填质量)/ `gripper`(夹爪组件质量在末端——**无论电机是否接线**;电机接线与否由硬件 yaml 的开关回答)。**两个正交事实**:profile 回答「挂什么质量」,yaml 开关回答「电机在不在总线」。出厂配置 = 官方一整套(`gripper: true`,profile 锁 `gripper`);夹爪装着但没接线 = 开关 false + profile `gripper` 的死重态(质量保留、执行器缺席);无夹爪 = 开关 false + `bare`(0.8 kg 剥离)。见 `app/backend/tuning.py`、`docs/HARDWARE_NOTES.md` #11。

**「锚点」一词退役。** 它曾是最小单元的名字,但那套房子同时指素材和序列里的引用 —— 两种东西共用一个词正是混淆的来源。现在素材叫位姿、序列里的块叫保持块,各回各家。

## 内核边界与部件关系

「什么属于内核、谁调谁、谁发什么事件、新东西放哪」四张表。**本文件是它们的唯一家** —— AGENTS.md 代码地图只链到这里,不抄副本。

### 内核边界

| 层 | 目录 | 内容 |
|---|---|---|
| **内核 Kernel**(物理地基,永不动) | `app/backend/arm/` + `app/backend/safety/` + `app/backend/core/controller.py` + `app/backend/core/activity.py` | 动词集:hold(急停走的就是它)/ move_to / settle / relax / set_float / follow;前置件:SafetyLatch + 运动闸门 + 互斥活动表(`decide`) |
| **时空编排引擎** | `app/backend/core/`(executor / floatlock / broadcaster / events)+ `app/backend/sequences/` | 位姿 / 序列 / 模板 / 时间轴 + 执行器 |
| **插件层** | `app/backend/actions/` + `app/backend/shutter/` | 动作插件框架与快门实现;插件够不到臂 |
| **入口层** | `app/backend/api/` | HTTP / WS 入口,只调 controller 与 store |

### 接口三件套(每个可替换部件:动作集 / 实现 / 使用者)

| 接口 | 动作集 | 实现 | 使用者 |
|---|---|---|---|
| **ArmDriver**(内核接口) | hold / move_to / relax / set_float / follow / set_gravity_correction / set_float_gains / reload_dynamics / read_state / connect / disconnect | `ArmSession`(真臂)、`SimArm` | **唯一:控制循环**(executor 拿的是 controller 注入的同一个实例)。前置件:SafetyLatch + 运动闸门。失败语义:出声回落 + SIM 徽章 |
| **ShutterDriver** | is_connected / ping / focus / shoot / pair / pair_smart / camera_connected / camera_status;失败**抛异常**不回布尔(「继续拍」还是「停整条」必须当场可辨) | `Esp32Shutter`(真板)、`SimShutter` | runner worker(经 ShutterProvider)+ 快门自检。**永不回落** —— 回落等于 SimShutter 把每一帧都谎报拍到 |
| **ActionProvider** | fields(触发表单)/ probe(健康)/ run(执行,阻塞常态) | entry_points + `app/plugins/` 目录两条发现路径 | runner worker,每 provider 一条;`ActionContext` 里**没有 arm** |
| **ActionContext** | 只读:sequence id/name、waypoint 位置与备注、触发时刻关节角、`emit()` 单向事件 | — | 动作插件 |

### 事件生产/消费映射

| 事件 | 生产方 | 消费方 |
|---|---|---|
| `sequence.started` / `sequence.done` / `sequence.aborted` | executor(块遍历) | `/ws` 的 `event` 主题订阅者(外部集成);前端状态走 state 流,不吃 event 流 |
| `pose.arrived` | executor(进站到位) | 同上 |
| `action.started` / `action.done` / `action.failed` | executor(provider 结果) | 同上 |
| `estop.engaged` / `estop.cleared` | 控制循环(它看见闩锁) | 同上 |
| `teach.captured` | 位姿 capture 端点(经 controller.emit_event) | 同上 |

事件三条铁律(全文见 `app/backend/core/events.py`):**单向不可否决**;有界队列、慢订阅者丢旧包(不拖停控制循环);**事实在知道它的地方发** —— 执行器发序列/动作、控制循环发急停。

### 新行为归属位置

| 要加的东西 | 挂到哪 | 闸门 |
|---|---|---|
| 让臂动的 HTTP 端点 | `app/backend/api/` 新路由 | `require_arm_available`;或在 `app/tests/test_motion_gate.py` 的 `NON_MOTION_ROUTES` 写明理由 |
| 新动作类型 | `ActionProvider`(entry_points 或 `app/plugins/`) | `check_shape` 形状闸门;ctx 无 arm |
| 新调参 | `app/backend/tuning.py` 模型 + 调参面板 | `Controller.apply_tuning` 分级(执行中拒一切、浮动中拒负载切换) |
| 新硬件事实 | `docs/HARDWARE_NOTES.md` | 已验证 / 待实测分开 |
| 新插件扩展点 | 先读 `docs/PLUGINS.md` | 「为什么触发源不是插件」 |
| 新语义事件 | `app/backend/core/events.py` + 在生产方 emit | 单向不可否决;慢订阅者丢包不阻塞 |

## 边界:刻意不拥有、刻意不做

| 边界 | 决定 |
|---|---|
| **感知**(看/听/懂) | 参考场景,不进内核。VLM 语音是未来的参考场景,用来证明「我们能实现」;平台只保证**外部智能能安全地指挥里面的臂**(事件流 + 触发源 + 租约,已存在) |
| **产出** | 归下游。平台给事件流,不管照片、资产、业务台账 |
| **设备** | 不锁。三平台(Win / Linux / macOS)可部署;真臂连接依赖操作系统的 CAN 驱动,传输层由**文档**说明,代码不做平台自动配置脚本;systemd / udev 是 Linux 参考部署,不是唯一部署 |
| **兼容** | 零承诺。形态与内容承载点随真实用户改变,不为假设的用户做版本化 |
| **轨迹录制** | 未来方向,**禁止照搬 LeRobot**,交互必须在使用上优于它。当前核心是位姿式(点位 + 序列) |
| **使能** | 文档 + 课程(M6)是使能材料,形态随真实下游定;现在只承诺文档 |
| **信任模型** | 保持现有:急停闩锁横切、运动闸门、插件够不到臂、触发源在闸门之下、agent 租约 —— 它就是「下游代码在一台 48V 臂旁边」的边界 |

## 模式的先后边界

- **先定**:概念模型、分层、词汇(本文件)—— 骨架
- **后做**:插件、参考场景 —— 骨架下的填充

插件层收敛成**四个扩展点而不是一个 hook 链**:动作插件(进程内,流程会等它)、操作 ops(进程内,面板级操作如配对/自检,设计已定、实现排队)、触发源(进程外 HTTP 客户端)、事件订阅(进程外 WS 客户端)。为什么是这些、为什么触发源不是进程内回调,见 [`PLUGINS.md`](./PLUGINS.md)。

摄影场景需要的"单次到位+拍"(点位姿 → 到位 → 稳定 → 触发 → 停住)是**使用层原子操作的最小闭环**,也是所有场景的公共操作,先于任何插件存在。

## 模式的对错,由场景验证

模式的试金石:**任何场景能否用这套积木 100% 表达出来,且不为"通用"付任何专用税。** 摄影是第一个考卷,不是唯一考卷;工业、语音是后面的考卷。能,模式成立;不能,说明抽象漏了东西 —— 那就修抽象,不是给场景开后门。
