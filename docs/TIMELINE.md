## 一句话

**这台机器剪的是物理时间。**

空间定位(可编程、可编排)是已有能力;这份设计是它在**时间维度上的呈现**。用户编排的不是视频片段,是臂在物理空间里的时间:块可以拖动、长度可以修剪、播放可以在块间暂停 —— 剪辑软件是人类唯一已经学会的「时间编排直觉」,这里把它借给一条 48V 的臂。剪出来的「成片」不是视频,是臂的一次真实执行。

## 时间轴模型

### 骨架块与块内标记

```
骨架层(板)    保持块 ── 过渡块 ── 保持块 ── 过渡块 ── 保持块
                ▏◉   ⏸   ◉▏          ▏◉··········■▏
细节层(钉子)   快门@2s 等待@3s 快门@4s    开录@起点   停录@终点
```

两层分工(决策过程与六个任务的手势对比见 timeline-model-comparison.html):

- **骨架块承载结构**:被拖动、修剪、整体重排。保持块/过渡块交替排列。
- **事件标记承载动作**:被点、微调、删除。钉在父块内部的时间位置上,**随父块移动与修剪**。

为什么动作不是块:脱钩在这台机器上是物理事故,不是剪辑瑕疵 —— 块模型里整体挪动一个站位要多选,漏选一个,快门就和姿态脱钩,拍完一整轮全是空片。标记挂父块让脱钩**结构上不可能**,与「`ActionContext` 里没有 arm 句柄」同一手法:让错的事够不到,而不只是禁止。

### 五条物理规则

1. **过渡块自动生成、不可删除、只可编辑。** 两个不同位姿的保持块相邻,臂必须物理地过去 —— 这不是设置,是物理。相同位姿的保持块相邻则不生成过渡块(等于「停到一半拍一张」)。
2. **事件标记可以钉在过渡块内部任意比例处**(如运动到 40% 开补光)。用劈开过渡块来表达中点 = 捏造一个从未示教过的姿态,禁止。
3. **位姿链接式复用。** 保持块只存位姿名,不存关节角;臂要动时拿名字去素材库取。**先告知再动手**:覆盖保存或删除一个被 N 条序列链接的位姿时,界面必须拦一句「正被 N 条序列用着」,确认才执行 —— 静默改变多条序列的物理路径,是「拍完一整轮全是空片」那一类失败。
4. **时间尺是计划尺,播放头走真实。** 保持块/过渡块的长度是**指令时长**(机器照做);动作的执行时长(如快门经 BLE 唤醒相机最长 6 秒)是**预估**,在标记上显示为半透明跨度;等待标记是**开放式**(不估)。执行时块可以被现实撑长。界面标清哪个数字是哪种 —— 时间尺永远不撒谎。
5. **执行中时间轴锁定,停止才解锁。** executor 正在逐块消费的结构不能在用户手底下改变;等待标记处的暂停也锁。预演不受限 —— 模拟随便改,从头再播就是。

## 预演与执行:两个动词

剪辑软件的 ▶ 播的是监视器画面;这台机器的 ▶ 可能意味着一条 48V 的臂真的动起来。两个动词必须分家,不共用一个按钮:

- **预演**:播放头走计划尺,监视器按时间轴播模拟姿态(过渡的缓动肉眼可见),**臂一动不动**。全界面只用灰阶 —— 预演不是机器状态,颜色通道一个都不亮。**诚实边界**:预演呈现的是**计划路径**(前端按关节空间插值 + 缓动计算),真臂走的是上游 `move_to` 的实际路径;两者应接近,不保证一致,界面与文档都写明这一点。
- **执行**:真臂跑。播放头走**真实进度**,监视器翻为实况,琥珀色点亮(当前块描边、横幅、光带)。事件标记在经过时按既有颜色语义闪白。

**等待标记对两者都生效**:预演播到它停住等点「继续」;执行播到它 executor 挂起等确认。

**监视器单视图全尺寸翻转**:一块 3D 视图,预演时整块播模拟(灰阶 + 「预演中·臂未动」横幅),执行/空闲时整块是臂实况。翻转是全视图级的 —— 没有画中画、没有局部小窗,模拟与实况永不同屏。「这是模拟还是真的」不需要标签,位置即语义。

## 布局:剪辑三区一屏

```
┌────────────────────────────────────────────────────┐
│ 顶部:4px 状态光带 + 序列名                [急停]     │
├──────────────┬─────────────────────────────────────┤
│ 素材库        │ 监视器(全尺寸 3D 视图)               │
│ 位姿 | 模板   │ 预演=灰阶模拟 / 执行·空闲=实况       │
├──────────────┴─────────────────────────────────────┤
│ 走带条:[▶预演] [执行(臂会动)]   时间码 / 预估总长    │
│ 时间轴(全宽):刻度尺 + 骨架块 + 块内标记 + 播放头     │
└────────────────────────────────────────────────────┘
```

- **素材库·位姿页签**:每个位姿一张卡 —— 名字、「被 N 条序列链接」徽标、「去这里」按钮(日常的「点哪去哪」不死,搬进了素材库)。底部「+ 录位姿」进示教流程(沿用 floatlock 示教链路,录完进素材库)。
- **素材库·模板页签**:模板卡 + 「用它」(进入逐站位替换位姿向导)。
- **时间轴是主角**,全宽常开:拖位姿上轴是最高频的编辑手势,素材库因此也必须常开可见。
- 急停顶条沿用(z-index 60 约定不变,见 [`AGENTS.md`](../AGENTS.md))。

可点的完整原型:[`editor-layout-skeleton.html`](./editor-layout-skeleton.html)(含预演/执行/急停/等待标记的行为演示与颜色纪律)。

## 模板

- **任意序列可「存为模板」**。模板 = 结构配方(站位数、各站停留时长、事件标记配方、过渡参数)+ 位姿槽位。**不存关节角** —— 别台机器、别的棚里示教的角度在你的棚里是错的,模板的价值是结构。
- **实例化 = 复印 + 向导**:向导逐站位引导示教新位姿(进素材库)并替换绑定,生成一条普通序列。
- **复印即脱钩,两不相干**:之后改模板、删模板,已生成的序列纹丝不动;序列改删重排也不影响模板。没有链接就没有看不见的后果 —— 不需要确认机制,也不需要版本/通知工程。
- v1 只做整条序列级模板;站位级配方(如「停 3s + 拍一张」)等真有人重复再长。

## 插件的位置

插件体系(entry_points 发现、runner 隔离、三道校验、FieldSpec 三控件 manifest,见 [`PLUGINS.md`](./PLUGINS.md))**原样继承**,变的只是动作的家:从 `waypoint.actions` 有序列表搬到**块内标记**。标记的参数编辑面板仍由 provider 的 manifest 渲染。动作依然是瞬发触发 —— 「持续」由设备自己维持(边运动边录 = 开录/停录两个标记夹住一个过渡块),**工作流线性的既定决策不破**(`backend/sequences/models.py` 开头)。

## 沿袭的既有约定(不因重构改变)

以下约定在 [`AGENTS.md`](../AGENTS.md) 维护,只列不重述:颜色是状态通道(四色独占机器状态,红/琥珀永不同尺寸同位置、永远配文字)、界面不许猜臂在哪(模拟画面必须标明是模拟)、急停在栈顶(z-index 60)、Esc 用原生监听、动作绝不跑在控制循环上、插件够不到臂、`0.0` 是假值、测试不写 `time.sleep`。

新约定只有一条增量:**预演不是机器状态,全灰阶** —— 四色通道在预演中一个都不亮。

## 三期路线

| 期 | 内容 | 边界 |
|---|---|---|
| v1 | 纯前端:三区界面 + 时间轴 + 素材库 + 预演/执行,全部跑在重写的 mock 上。**直接替换现有前端**(卡片板组件删除,不并行),零后端改动 | mock 按新数据形状(位姿库 / 块 / 标记 / 模板)重写,形状即契约 |

| v3 | 执行对接 + 模板向导（已实施） + 真机验证（待硬件） | 含 [`HARDWARE_NOTES.md`](./HARDWARE_NOTES.md) 待实测项回填 |

## 刻意不做

- **路径形态**(关节空间 / 笛卡尔直线 / 弧线):过渡块面板留第三个区,标「后端能力待定」—— 交互先设计,不承诺
- **真·多轨并行**:两个受控执行体并行,砸「工作流线性」铁律,急停语义与碰撞面全要重估
- **条件 / 分支规则引擎**:沿用 models.py 的既定决策
- **模板版本 / diff / 更新通知工程**:副本式没有链接,没有要通知的东西
- **热编辑**(执行中改动立即生效):臂在飞的时候抽换它前方的轨道
