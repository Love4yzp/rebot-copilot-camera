# 荣耀机械臂需求提炼

## 1. 背景与定位

- 荣耀影像侧在推进**新品首销**相关内容制作。
- 痛点：市面摄影机械臂基本以相机为载体 → 相机重（承重普遍 5kg 级）→ 导致**体型大、轴数少**。
- 思路：改用**手机拍摄**（仅 200 多克），机械臂整体可做小；借轻载换取更小的体积 + 更多轴 + 滑轨，实现更复杂的运镜。
- 主要用途：**室内运镜为主，产品拍摄运镜**。
- 

## 2. 硬件需求（硬指标）

| 项 | 要求 | 备注 |
| --- | --- | --- |
| 承重 | **1 公斤以内** | 手机 200 多克为主，备一台不足 1kg 的轻量相机（机身+镜头一套） |
| 拍摄载体 | **手机为主，相机为辅** | 手机夹在机械臂末端拍摄 |
| 轴数 | **6 轴**（不带爪子） | 用户误以为 7 轴+滑轨；朱耀晖澄清：不带爪子=6 轴，爪子的旋转轴算进去仍是 6 轴，爪子只做张合 |
| 爪子 | **不需要** | 用户明确"爪子意义不大"  comm |
| 末端接驳件 | **3/8 或 1/4 英寸标准螺口/螺纹** | 用于装拍摄接驳件；用户说"结构调整难度低、好调" |
| 滑轨 | 需要（底部前后位移） | 用于拓展运镜可能性 |

供方现状：两款量产臂承重 **1.5kg / 2.5kg**、均 6 轴（不带爪子）、自带底部滑轨前后位移 —— **完全覆盖 1kg 需求**。

## 3. 运镜 / 软件需求

1. **多点打点**：A→B→C→D 逐点打点，手动把臂拖到位后"打一个点"记录，形成动作编排顺序。
2. **曲线平滑过渡**：点与点之间**不是纯直线**，要能带弧线（"三个点画一个圆"、拍手机"正面→转一圈到顶部→再转回正面"）。
3. **缓入缓出**。
4. **倍速档位**：预设 **0.25 / 0.5 / 1 / 2 / 4 倍速**（逐字稿还提到一次"3 倍速"），**只需档位，不要自定义精确参数**——"按倍速调节，不需要设具体值"。
5. **不要编程**：明确倾向打点而非代码编程（编程涉及调视觉、门槛高）。
6. 快门、滑轨滚动等动作 → 接受"插件"方式（还提到"遥控快门也能解决"）。

## 4. 交互与部署

- **网页端即可**，认可现有网页交互逻辑（用户看到原型后："比我的需求更精细、可控更多"）。
- **局域网 + 手机浏览器访问**操作（手机/平板/折叠屏）；**不需要独立 APP**。
- 连接方式：一台主机（电脑）用 **USB 连机械臂控制线**，手机浏览器走局域网访问该界面。
- 系统：**Windows 和 Mac 均可**。
- **远程投屏 / 拍摄 / 预览 / 快门**：荣耀自己的产品已具备，用户**主动提出不用 Seeed 再开发**（"功能越多负载和压力越大，时间紧迫"）。

## 5. 关键应用场景

- 常规室内产品拍摄运镜。
- **车内复杂镜头**：主驾/副驾/后排**多人机位切换**，**不拆车顶、不重新布光**。剧情逻辑：A 说话拍 A → 快讲完切 B → 再切 C（后排）。第三视角用 GoPro / Action Nano 记录拍摄过程当花絮。

### 工程侧跟进点（供判断，非会议待办）

- 原型已覆盖打点 + 平滑过渡 + 快门/滑轨插件，需对照确认：
  - **倍速档位（0.25/0.5/1/2/4）** 是否已实现；
  - **弧线过渡（三点画圆）** 是否已实现。
