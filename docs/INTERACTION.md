# 交互骨架详细设计

**状态:设计稿 v1,已呈现待确认。** 这份文档是「交互骨架」(ARCHITECTURE.md 三个不变量的第二层)的落地设计:布局、流程、参数隐藏、接口。概念模型与词汇的权威定义在 [`ARCHITECTURE.md`](./ARCHITECTURE.md),这里不重复,只讲界面怎么长、后端加什么。

## 核心转变:从「脚本编辑器」到「锚点卡片板」

默认界面就是**使用层**:一屏大卡片,点哪张去哪张。编辑能力全部收进「配置模式」。诊断出现界面不直觉的四条根因:

- 主界面是脚本编辑器心智:点位列表 + 关节弧度数字,摄影师看不懂也不需要看
- 主动词是「播放整条序列」,但真实工作流是「点一个锚点 → 到位 → 触发」—— 单次到位没有入口
- 触屏不友好:HTML5 拖拽排序、`prompt()`/`confirm()`、双击重命名、右键删除
- `duration_s`、`settle_ms`、`on_failure`、`retries`、`timeout_s` 全部裸露

## 布局(触屏优先)

```
使用模式(默认,天天用)
┌────────────────────────────────────────────────────┐
│ 四方位 ▾   锚点板                    ● 就绪   ✋急停 │
├──────────────────┬─────────────────────────────────┤
│                  │  ┌──────────┐  ┌──────────┐      │
│                  │  │  正面     │  │  右 45°   │      │
│   3D 视图        │  │  触发×3   │  │  触发×1   │      │
│  (可折叠)        │  │  ● 已到位 │  │          │      │
│                  │  └──────────┘  └──────────┘      │
│                  │  ┌──────────┐  ┌──────────┐      │
│                  │  │  侧面     │  │  俯拍     │      │
│                  │  └──────────┘  └──────────┘      │
├──────────────────┴─────────────────────────────────┤
│ ▶ 播放全部        移动中… ▮▮▮░░ 稳定中   [编辑]     │
└────────────────────────────────────────────────────┘

配置模式(点「编辑」进入,偶尔用)
- 卡片出现编辑把手:改名、触发配置、删除、排序
- 底部出现「+ 录锚点」→ 进入示教流程
- 集合可新建/重命名/删除
```

卡片状态机:`空闲 → 移动中(呼吸动画)→ 稳定中 → 触发中 → 已到位(实心高亮,臂保持)`。再点下一张,状态自然转移。

## 三条核心流程

**日常使用(原子操作,零学习):** 点一张锚点卡 → 臂自动到位 → 自动稳定 → 自动触发 N 次 → 停住。全程屏幕上只有一个动作:点卡片。

**录锚点(示教):** 配置模式 →「+ 录锚点」→ 臂进入零力拖动 → 手拖到位 → 松手自动锁定(现有 floatlock)→ 点「保存」→ 自动起名可改 → 顺带设触发(默认 1 次)。

**模板向导(范式溶解成积木,零后端改动):** 新建集合时选「空白」或预置模板(如「四方位」)。模板不是特殊对象,是一个引导流程:「把臂拖到【正面】→ 保存 → 拖到【右 45°】→ …」依次预填名字录点。录完就是普通锚点,可改可删可重排 —— 模板到此溶解完毕。

## 参数隐藏方案

| 后端字段 | 界面呈现 | 说明 |
|---|---|---|
| `duration_s` | 三档:慢 / 标准 / 快 | 档位映射具体秒数,模型字段不动 |
| `settle_ms` | 隐藏,全局默认 | 只在高级设置出现 |
| `on_failure` / `retries` / `timeout_s` | 从界面删除 | 后端字段保留,UI 固定合理默认 |
| `focus_first` | 触发配置里的开关 | 真需求,保留 |
| 触发 N 次 × 间隔 T | 次数步进器 + 间隔预设档 | 需后端小改(见下) |
| 关节弧度数字 | 永不出现 | 3D 视图 + 状态文案替代 |

## 后端改动(仅两处)

**① goto 端点 —— 使用层原子操作的后端:**

```
POST /api/routines/{rid}/waypoints/{index}/goto
```

- 挂 `require_arm_available` 运动闸门(急停时 409)
- 取该 waypoint 构造**单锚点临时 Routine**,`validate_sequence([当前位, 目标位])` 预检路径,`controller.play(临时 routine)`
- 复用 executor 全部逻辑:首段限速(goto 永远走「首段」保护)、到位判定、settle、动作执行、急停 abort、WS 进度广播
- 到位后臂保持在锚点(沿用 routine 结束行为;真机 MIT 末位保持,列为真机验证项)
- 播放中/示教中再点 → 409,UI 提示「等当前动作完成」

**② ShutterAction 加两个可选字段:** `count: int = 1`、`interval_s: float = 0.0`。executor 在 `_run_fallible_action` 内循环 count 次,间隔用现成 `_sleep_until` 模式。带默认值,旧 JSON 兼容,不动 schema_version。

其余端点(capture/play/teach/ws/CRUD)一律不动。

## v2:色彩语义与状态可信度

**状态:已实现。** 骨架落地后暴露出两类问题 —— 颜色只是装饰、界面会对臂的位置说谎 —— 这一轮把两者一起修掉。

### 颜色是状态通道,不是装饰

底盘全灰阶(`--ink` / `--body` / `--edge` / `--mark` / `--mark-dim`),**没有品牌强调色**。原来的蓝色 accent 被整个删掉:它同时充当按钮、进度、选中、链接,颜色因此失去含义,而「臂正在朝人移动」这个状态只配到了一段柔和的蓝色呼吸。

彩色只有四个,各自独占一个机器状态,借用操作者已经会读的约定:

| Token | 含义 | 借用 |
|---|---|---|
| `--stop` 红 | 已急停 | 通用停止 |
| `--motion` 琥珀 | 臂在动,别伸手 | 机械单元警示灯 |
| `--ready` 绿 | 到位、保持 | 安全 / homed |
| `--expose` 白 | 动作执行中 | 曝光 = 光 |

`--expose` 这个名字是权宜:它在架构上表示「动作执行中」(中性词,见 ARCHITECTURE 的词汇基调),白色是因为第一个动作插件恰好是快门。界面上的字是**触发**,不是「曝光」。再加第二种动作插件时,颜色不变,名字该改。

红/琥珀是 protan/deutan 易混对,所以三重冗余:不同尺寸、不同运动形态(急停脉冲 / 运动扫描)、永远配文字。

**Tally 条**(`TallyRail.tsx`)是签名元素:顶端 4px 满幅光带,直接报机器状态。操作者站在臂旁读不到 12px 状态字,但两米外余光能读一条横贯屏幕的光带 —— 这正是棚里 tally 灯存在的理由。

排版三层:`Saira Condensed`(自托管 latin 子集,机身丝印感,只承载 Latin 标签与按键号)、PingFang SC(锚点名,`clamp(26px, 2vw + 16px, 40px)`)、等宽(数字,tabular)。

### 状态可信度

卡片状态机改为 `idle → pending → moving → settling → acting → arrived`,`arrived` **只由 `phase === "done"` 触发**。三条硬规则:

- **`phase` 为空不等于到位。** 原实现把 `null` 当 arrived,点卡瞬间就亮「已到位」。
- **陈旧的 `done` 不算数。** Controller 保留已完成的 executor,socket 会持续重播上一次的 `done`;所以 `pending` 只被*运行中*的 phase(moving/settling/acting)解除,超时则丢弃声明而非升级它。
- **急停或示教立即作废 `target`。** 臂被冻在别处或即将被人推走,继续亮「已到位」就是界面在撒谎。

完整播放时 `waypoint_index` 在收尾时会 +1 越界(`_advance_waypoint` 先自增后判断),前端夹紧到 `total - 1`。`mock/plugin.ts` 同步对齐:结束时保留 playback 而不是置 null。

### 其余落地要点

- **急停层级**:`.estop-bar` 置于 z-index 60,在所有遮罩(40)之上。此前示教弹层的遮罩会吞掉急停按钮的点击,而示教正是双手在臂上的那个模式。`TeachRail` 另带一个自己的急停。
- **Esc 路由**:弹层用*原生*监听在面板上截停 Esc(React 合成事件的 stopPropagation 拦不住 window 级监听),有弹层时关弹层,无弹层时急停。
- **反馈回到手指**:单锚点进度填充在卡片内部,不在底部进度条;快门是卡面一帧白闪。
- **配置模式换地面**:整块板换成浅色工作台底 + 网格,前注意级别区分「点了臂会不会动」。卡片带「试跑」,录完不用切模式验证。
- **触屏**:3D 预览由 hover 改为选中语义并收进抽屉;`title=` 里的信息(连接状态、进度、Esc)全部上屏。
- **无障碍**:全局 `:focus-visible`、`prefers-reduced-motion`、`--mark-dim` 提到 7:1、弹层焦点陷阱 + `aria-modal`。
- **数字键 1–9** 触发对应锚点(卡片角上的编号即按键号),兼容发数字的脚踏。
- **删除锚点改为撤销**(8 秒 toast),复用 `POST /waypoints` 的 `index` 按原位重建;错误 toast 不自动消失,带「看日志」直通 `LogDrawer`。

## 刻意不做

- **不拆 Collection / Sequence 两个后端实体** —— Routine 一个模型同时承载「集合」与「播放顺序」;独立编排实体等真有人要再长(ARCHITECTURE 里 Sequence 本就是「可选,高级」)
- **不做缩略图/照片回显** —— 依赖相册链路,插件阶段再说,卡片留好位置
- **不做连续点按排队** —— 409 + 提示足够;排队是编排的变体
