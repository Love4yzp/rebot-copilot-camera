时间轴模型对比：动作是块还是标记？

这是一台机械臂运动序列的「剪辑软件式」编辑器 —— 用户编排的不是视频片段，而是臂在物理空间里的时间。 本文用同一条演示序列对比两种数据模型：外设动作（快门 / 等待 / 录制 / 补光）应该表达为 时间轴上的块，还是块内的标记。

内部设计文档 · 演示序列：产品拍摄，四个站位（正面 → 右45° → 侧面 → 俯拍） · 统一刻度 50px/秒 · 总长 20.5s

→ 标记挂在过渡上，随块移动 / 修剪

结论：方案 B —— 骨架块 + 块内标记

  1. 脱钩在这台机器上是物理事故，不是剪辑瑕疵。视频剪辑里音画脱钩只是回放难听；这里快门与姿态脱钩， 意味着臂停错了位置还按了快门 —— 一整轮拍摄全是空片。块内标记让「动作」和「姿态」在数据结构上是同一个物体， 脱钩从「容易犯的错」变成「结构上不可能」—— 让错的事够不到。
  2. 时间轴的第一读者是骨架。任何人扫一眼要先回答：几个站位？各停多久？之间怎么动？ 纯块模型里零时长的快门薄片和承载站位的保持块在同一层级竞争注意力 —— A 版 15 个元素里只有 7 个是骨架； B 版一眼就是 7 个块。
  3. 剪辑软件几十年收敛出的分工：片段承载结构（拖 / 剪 / 整体挪），标记承载事件（点 / 微调 / 删）。 这不是审美偏好，是两种操作频率的分离 —— 结构改动少而大，事件调整多而小。

代价：B 多一层「块内」细节视图，首次接触的直觉成本略高于纯块。 但纯块的直白优势，在第一次「中间加一张」时就用光了 —— 从那一刀劈开开始，用户就在替数据结构打工： 心算时长、手动合并、框选防漏。
