# reBot 运动策略笔记

从 [`ZhuYaoHui1998/rebot-b601-102-record-demo`](https://github.com/ZhuYaoHui1998/rebot-b601-102-record-demo) 的
`Python_SDK/rebot_b601_rs_record_dance.py` 提炼：**reBot Arm 102 主臂录制 → B601-RS 从臂回放**。

这份只记两类东西：

- **物理事实** —— 硬件/固件层面为真、换个上位机也不变的量和坑。
- **策略** —— 那份 demo 为了不把臂摔了而采取的做法，以及每条背后的物理原因。

## 先读这段：能抄的不是代码

| | 那份 demo | 本项目 |
|---|---|---|
| 栈 | LeRobot 插件 `lerobot_robot_seeed_b601` + `lerobot_teleoperator_rebot_arm_102` | `reBotArm_control_py` + `motorbridge` |
| 形态 | 主从遥操作，30 Hz 录帧回放 | 无主臂，零力拖动示教 |
| 单位 | 动作空间**度** | **弧度** |
| 关节名 | `shoulder_pan.pos` … `gripper.pos` | `joint1`..`joint6` + `gripper` |

**下面出现的 `follower.motors`、`bus.poll_feedback_once()`、`get_observation()`、
`send_action()`、`joint_directions`、`max_relative_target` —— 我们一个都没有。**
写它们只为指出证据在 demo 的哪一行，不是让你去调。

能搬的是：**这些量是多少，以及为什么必须这么做**。见 [`HARDWARE_NOTES.md`](./HARDWARE_NOTES.md)。

## 一、物理事实

### 1.1 两条臂走两条完全不同的链路

| | 传输 | 端口 | 参数 |
|---|---|---|---|
| Arm 102 主臂 | 串口 | `/dev/ttyUSB0` | 1 000 000 baud |
| B601-RS 从臂 | CAN | `can0` | socketcan |

主臂只被 `get_action()` 读，从臂只被 `send_action()` / `get_observation()` 写读。
两条链路的故障模式不共享 —— 主臂掉线表现为动作卡住，从臂掉线表现为命令石沉大海。

### 1.2 七个关节；demo 的阈值是度，我们是弧度

demo 的关节名（跟我们的 `joint1..joint6` + `gripper` 一一对应）：

```
shoulder_pan  shoulder_lift  elbow_flex  wrist_flex  wrist_yaw  wrist_roll  gripper
    J1             J2            J3          J4         J5         J6         G
```

**搬阈值时要换算。** 原始 DM demo 是 **0.003 rad**，这份写成 **0.172 度** —— 同一个量。
我们走弧度，抄回去是 0.003 rad，不是 0.172。

即使在 demo 里也是两套单位并存：命令是度，电机反馈是弧度。**混单位是这类代码最常见的错。**

### 1.3 夹爪的行程被放大，速度上限必须单独一档

demo 那边夹爪的配置 scale 是 **6** —— 命令给 1 度，到电机是 6 度。
我们这边没有这个 scale，但**同一个物理现实还在**：夹爪一个电机（`0x07`）驱动 URDF 里
两个指关节，不是 1:1（`HARDWARE_NOTES.md` §3）。**小命令 = 大行程。**

结论跟栈无关：**夹爪的速度上限不能和臂关节共用一个数**，要低一档。demo 的取值：

| 场景 | 臂 (deg/s) | 夹爪 (deg/s) |
|---|---|---|
| 主从安全同步 | 15 | 5 |
| 循环首尾衔接 | 15 | 5 |
| 正常回零 | 15 | 5 |
| **高温回零** | **8** | **3** |

高温回零比人工回零更慢 —— 已经热了，再多产一份热是坏事。

另一条同样与栈无关：**下一段插值的起点要用臂实际到达的姿态，不是你上一次发出去的命令。**
限幅、行程放大、跟随误差都会让两者不等，拿命令值当起点，误差会在整段回放里累积。

### 1.4 温度是真正的约束，不是力矩

RobStride 电机反馈里的 `t_mos`（MOS 管温度，°C）是唯一的过载指标。三档阈值，构造时
强制校验 `报警 < 回零 < 断开`：

| 阈值 | 默认 | 行为 |
|---|---|---|
| 报警 | 80 °C | 只显示，运动不变 |
| 回零 | 100 °C | 停当前动作 → 慢速回零 → 断电机 |
| 断开 | 140 °C | 立即中止，**不回零**，直接断 |

### 1.5 电机反馈是请求/应答，不主动推

RobStride 的状态是**问一次答一次**。不发请求、不等回包，读到的就是上一次的缓存值。
demo 里体现为三步（每电机 `request_feedback()` → 总线轮询一次 → 读回状态），
少中间那步就拿到陈旧数据 —— **调用名我们没有，但"必须先请求再读"这条对 motorbridge 一样成立。**

两个可直接搬的判据：

- **所有 `t_mos` 恰好等于 0.0 = 反馈没更新**，不是"很凉快"。要显式告警。
- **一个有效温度都读不到时，必须明说「温度保护不可用」**，不能静默继续跑。

### 1.6 控制 30 Hz，遥测 2 Hz

遥测对每个电机做一次 CAN 往返（7 个电机 × 请求+轮询+读）。跟控制循环同频会把 CAN 打满。
**两个频率必须分开。**

### 1.7 断连即失力矩

`disable_torque_on_disconnect = True` —— 断开就掉力矩，**臂自由落体**。
所以任何正常退出路径都是「先回零 → 保持 0.30 秒稳定 → 再断」。顺序反了就是摔臂。

（本项目的急停语义相反：冻结 `q_target` 保持力矩。见 `HARDWARE_NOTES.md` §1。）

### 1.8 smoothstep 的峰值斜率是 1.5

`3α² − 2α³` 在 α=0.5 处斜率 1.5。所以想让峰值速度真的不超 `v_max`：

```python
duration = 1.5 * abs(end - start) / v_max
```

漏掉这个 1.5，实际峰值会超上限 50%。全局所有限速插值（回零、首尾衔接、槽位过渡）
都用同一个公式，取所有关节的最大值，再和一个最小时长取 max。

## 二、策略

### 2.1 底层限幅被关掉了，所以每条路径都自己限速

demo 把 LeRobot 的单周期相对目标限幅关了（`max_relative_target = None`）。
理由：那个限幅会把一次平滑回放拆成多次「追赶」，动作顿挫。

**这条对我们最重要的地方**：下面 2.2–2.10 的所有限速，是在**没有底层安全网**的前提下写的。
我们这边同样没有这样的限幅 —— 所以这些不是"额外的保险"，**是唯一的保险**。
删掉任何一处，底下不会再兜住。

（附带一条工程习惯：demo 压那条刷屏日志时，用的是**只匹配该条前缀**的过滤器，
CAN 错误、电机故障、温度告警一律不动。压日志别压成一片。）

### 2.2 五个模式，禁止从回放姿态直接跳到主臂命令

```
FOLLOW ─┬─> RECORD
        ├─> TRANSITION ──> PLAYBACK
        └─> SYNC_TO_LEADER ──> FOLLOW / RECORD
```

回放中的姿态可能离主臂**很远**。一个控制周期内切成 raw leader 命令 = 一次瞬时大跳。
所以从 `PLAYBACK` / `TRANSITION` 出来必须先进 `SYNC_TO_LEADER`：

- 每周期朝主臂当前位姿走一步，步长 `speed_limit × control_period`；
- 所有关节都进 `LEADER_SYNC_TOLERANCE_DEG = 0.50` 才算对齐；
- 对齐后才恢复 `FOLLOW` 或才真正开始录制。

**对应到我们**：没有主臂，但「当前姿态」和「要切进去的那个模式期望的姿态」之间
一样可能差很远 —— 回放中途切拖动示教、切 goto、切回零，都是同一个问题。
**先限速归位、到位了再交接**，中间那段不能是一步跳。

### 2.3 录制槽在对齐前不清空

想录制时若正在回放，先记 `pending_record_slot`，进同步；**对齐后才清槽并开录**。
中途按 `s` 或再按同一个录制键 = 取消待录制，同步继续，**旧数据还在**。

同步路径本身不进录制 —— 对齐那一帧是录制的第一帧，之前的追赶轨迹不要。

### 2.4 录制是「低通 + 双重去抖」

```python
filtered = 0.35 * current + 0.65 * previous       # RECORD_FILTER_ALPHA
```

存帧要同时满足两个条件：

- 距上一帧 ≥ `MIN_RECORD_INTERVAL_S = 0.01` s（限上限帧率）
- 任一关节相对上一存帧变化 ≥ `MIN_JOINT_CHANGE_DEG = 0.172` 度（静止时不产帧）

结果是**变间隔时间戳**的帧序列 `(t, action)`，`t` 相对录制起点。静止段几乎不占帧，
快速段密。回放靠时间戳插值，所以变间隔无所谓。

### 2.5 录制收尾要补两帧

停止录制时追加：

1. **保持帧**：最后姿态 + `END_HOLD_TIME_S = 0.15` s。让动作有个落点。
2. **循环衔接帧**（仅 `play_loop`）：`frames[0].action` 的副本，时间戳 =
   `frames[-1].t + blend_time`，`blend_time` 按首尾姿态差和 §1.8 算出来，最少 0.60 s。

第 2 条是关键。**固定短过渡（原 demo 的 0.30 s）在首尾差异大时是一次猛烈回跳。**
按距离自动延长，峰值速度才受控。

### 2.6 回放：bisect + smoothstep

```python
playback_t = elapsed % duration if loop else elapsed
right = bisect.bisect_right(frame_times, playback_t)
alpha = smoothstep((playback_t - a.t) / (b.t - a.t))
action = lerp(a.action, b.action, alpha)
```

`duration <= 1e-9` 和 `segment <= 1e-9` 都要单独挡，否则除零。

切换槽位时不直接跳到第一帧：从 `last_sent_action`（没有就现读一次观测）经
**固定 0.60 s** `TRANSITION` 平滑过去。

### 2.7 启动时先读一次真实姿态

第一次回放的过渡起点必须来自**实际读到的臂姿态**。不读就默认零位 ——
而开机时臂可能停在上一次的任何地方，那一下就是从零位到首帧的瞬时大跳。

### 2.8 退出：Esc 和第一次 Ctrl+C 走同一条路

1. 只置一个标志、停主循环 —— **信号处理函数里不下发运动**；
2. 关电机之前保持使能，读一次当前姿态作为回零起点（读不到就退回最后一次命令值；
   两个都没有就打印「请手动扶住机械臂并断电」并**跳过回零** —— 盲目运动比不动更危险）；
3. 按最大关节位移算时长（最少 3.0 s），smoothstep 插值到全零；
4. 再发一次精确零位，稳定 0.30 s；
5. 才断开。

**第二次 Ctrl+C** 只置「中止回零」标志，回零循环每步检查后返回。
**收尾路径里不 raise。** 连接阶段的 Ctrl+C 例外 —— 那时还没接管，无法安全下命令，
直接抛出即可。

**异常退出不回零。** 因为异常往往意味着通信或反馈已经不可信，此时的插值命令也不可信。

### 2.9 高温回零期间继续测温

回零过程按遥测周期继续读最高 `t_mos`。中途冲到断开阈值就**立刻放弃回零、直接断**。
回零本身也要耗时耗电流，坚持走完可能比停在半路更糟。

### 2.10 主循环的两个时序保护

**通信卡顿后不要补执行积压的命令。** 落后超过 5 个控制周期就把下一拍对齐到当下，
否则臂会用一串"追赶"命令高速补完卡住期间的整段轨迹。

**停止请求来自另一个线程。** 停止可能在本周期的 sleep 期间到达 —— 睡醒后、发命令前
再检查一次停止标志，否则退出后还会多执行一帧。

按键 0.20 s 去抖。共享状态在同一把可重入锁下改。

## 三、对本项目有用的部分

| 那份 demo 的做法 | 对应到本项目 |
|---|---|
| 录制低通 0.35 + 0.003 rad 去抖 + 变间隔帧 | 示教轨迹录制的参数起点（**换成弧度**） |
| 回放按时间戳 bisect + smoothstep 插值 | 轨迹回放 |
| 循环首尾按距离算衔接时间，不用固定值 | 循环拍摄动作必需，否则每圈一次回跳 |
| 「远姿态 → 实时命令」必须经限速归位 | 示教↔回放↔goto 之间切换同理 |
| 限速时长公式带 1.5 系数 | 任何 smoothstep 插值都要带 |
| 三档温度阈值 + 高温回零更慢 | 长时间拍摄的过热保护，我们目前**没有**这条链路 |
| 反馈全 0 = 陈旧；无有效温度 = 保护不可用 | 同上，接温度时一起做 |
| 卡顿后不补积压命令 | 控制循环通用 |
| 断连掉力矩，所以先回零后断 | **别照搬。** 本项目断连不掉力矩，急停是 hold 住不放，见 `HARDWARE_NOTES.md` §1 |

**待重测**：速度上限（臂 15、夹爪 5 deg/s）和温度阈值（80/100/140 °C）都是那台空载
LeRobot 臂上的经验值。我们挂佳能机身后负载不同（`HARDWARE_NOTES.md` §B2），
上机要重测，别直接写进配置当默认值。
